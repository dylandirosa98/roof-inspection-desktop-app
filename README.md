# Spartan Roof Inspection

Offline-first, inspector-facing desktop software for reviewing roof photos, validating local hail-damage detections, and generating claim-support PDF reports. It is designed for inspection environments where reliable internet access is not guaranteed.

## Download For Windows

1. Open the [latest release](https://github.com/dylandirosa98/roof-inspection-desktop-app/releases/latest).
2. Download `Spartan-Roof-Inspection-Setup.exe`.
3. Double-click the downloaded file and complete the installer.
4. Open **Spartan Roof Inspection** from the Start menu or desktop shortcut.

The installer includes the application, local ONNX hail-damage model, ONNX Runtime, and WebView2. No repository clone, terminal, Go, Node.js, Wails, or internet connection after installation is required.

Windows may show a SmartScreen warning until the installer is code-signed. Choose **More info** then **Run anyway** only when the installer was downloaded from this repository's GitHub Release.

On first launch, the app starts with an empty local database. Customer images and reports remain on that computer.

## Features

- Local ONNX hail-damage inference with 640x640 letterbox preprocessing and non-maximum suppression.
- Editable image annotations with explicit reviewer approval.
- Approved damage photos only in the report; approved empty annotations document no damage and are excluded.
- SQLite-backed projects, annotations, report metadata, and last generated report path.
- Letter-size PDF reports with the Spartan Exteriors logo, photo notes, and adaptive pagination.
- Confirmed project deletion with cascading cleanup of local project, annotation, review, and report records while preserving the original roof-photo files.

## Engineering Decisions

The following source links are pinned to a specific revision so the referenced implementation and tests remain available as the project evolves.

### Offline-first inference

Roof inspections can take place without reliable connectivity, so the application runs its YOLO model locally through ONNX Runtime rather than depending on a hosted detection API. The small model can run on typical laptops; accepting a limited local compute budget was worthwhile for reliable analysis without uploads, API availability, or a network connection.

```go
inputTensor, err := ort.NewTensor(
	ort.NewShape(1, 3, 640, 640),
	inputData,
)

session, err := ort.NewAdvancedSession(
	resources.Path("models", "roof-hail-v1.onnx"),
	[]string{"images"}, []string{"output0"},
	[]ort.Value{inputTensor}, []ort.Value{outputTensor}, nil,
)
```

### Aspect-preserving model input

The model requires 640x640 input, but roof photos vary in size and aspect ratio. Each source photo is fitted onto a square letterboxed canvas instead of being stretched or cropped, preserving the entire image without distorting damage shapes. The preprocessing retains scale and padding so boxes can be translated from model coordinates back to the original full-resolution image.

```go
fitted := imaging.Fit(original, 640, 640, imaging.Lanczos)
xOffset := (640 - fitted.Bounds().Dx()) / 2
yOffset := (640 - fitted.Bounds().Dy()) / 2

return PreparedImage{
	Model: imaging.Paste(canvas, fitted, image.Point{X: xOffset, Y: yOffset}),
	Scale: float32(fitted.Bounds().Dx()) / float32(original.Bounds().Dx()),
	PaddingX: float32(xOffset), PaddingY: float32(yOffset),
}, nil
```

### Detection post-processing

Raw model candidates are confidence-filtered and then processed with non-maximum suppression. Sorting by confidence preserves the strongest prediction when multiple boxes identify the same area, keeping review screens and reports focused on actionable detections.

```go
sort.Slice(sortedDetections, func(left, right int) bool {
	return sortedDetections[left].Confidence > sortedDetections[right].Confidence
})

for _, candidate := range sortedDetections[1:] {
	if iou(best, candidate) <= iouThreshold {
		remaining = append(remaining, candidate)
	}
}
```

### Responsive image review

Loading full-resolution photos across a project grid made the initial review experience laggy. The application generates a compact 250x250 JPEG preview for the interface while keeping the original file path for full-resolution inference and report generation. This keeps browsing responsive without placing large customer photos in SQLite.

### Local persistence and resilient batch processing

Projects contain a manageable amount of data and must remain usable offline, making SQLite a better fit than a remote service. The schema stores project folders and image metadata locally, and sqlc generates typed Go access to explicit SQL queries. During analysis, one unreadable or invalid photo does not block the rest of the project: successful images are retained and all failures are returned together with their image IDs.

```go
var analysisErrors []error
for _, image := range images {
	_, err := a.AnalyzeImage(image)
	if err != nil {
		analysisErrors = append(analysisErrors, fmt.Errorf("image %d: %w", image.ID, err))
	}
}
return errors.Join(analysisErrors...)
```

## Processing Pipeline

1. Import a folder of roof photos and generate lightweight review previews.
2. Letterbox each source image to the model's 640x640 input without cropping or stretching it.
3. Run local YOLO inference through ONNX Runtime, then apply confidence filtering and non-maximum suppression.
4. Map detections back to original photo coordinates for inspector review and editing.
5. Require explicit approval before using reviewed damage photos in a report.
6. Generate a paginated letter-size PDF from approved damage photos and optional notes.

The backend tests target inference-pipeline risks that can silently produce incorrect annotations: model-output tensor layout, boundary clipping, letterbox coordinate reversal, and overlap suppression. PDF tests cover adaptive pagination.

## Workflow

1. Create a project from a folder of roof photos.
2. Run local analysis.
3. Edit boxes and add optional notes.
4. Approve each reviewed image. Approved images with damage boxes are report candidates; approved images with no boxes remain excluded.
5. Enter report details and generate the PDF.
6. Delete obsolete test or inspection projects from the sidebar when they are no longer needed. Deletion removes application records only; source photos remain in their original folder.

Development builds store the SQLite database at `data/app.db`. Packaged Windows builds store application data under `%LOCALAPPDATA%\Spartan Roof Inspection`. Do not commit customer images, reports, or databases. Obtain permission and remove customer information before sharing a demo.
